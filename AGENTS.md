# Vector Gate working rules

Read brief.md, docs/source-lock.md, and audits/_MASTER-TEMPLATE.md before changes.
The template snapshot is provided locally and ignored by git; refresh it from the
hub when continuing in a new checkout. Follow the hub's current CLAUDE.md for fleet integration.

The source-lock comparator gate is complete. Do not change pinned fixture bytes without
repeating independent checks. Keep one verifier path; the deliberately broken experiment
may omit only canonical-S enforcement. Never replace computation with canned verdicts.

The shipped theme is dark only, as required by the master template. Broken mode requires
an explicit learner action. Do not add a theme switch, second crypto centerpiece, or a
validation badge. Keep equation results, scalar range, final decision, and evidence scope separate.

Run npm test, npm run build, npm run test:a11y, and npm run test:mutations.
Commit reviewed real work before mutation runs. Mutations must always restore the source;
a missing browser or failed server is BLOCKED, never a mutation kill.

See docs/verification.md for the verification flow. Do not mark browser/a11y gates passed,
GitHub creation, deployment, or fleet integration complete without observing them.
